Classes & Objects

This session introduces the idea of the class and objects created from a class. It shows how this way of organising your code can help you to build sketches that model aspects of the world in meaningful ways. Classes and objects enable you to handle and control multiple items in your sketches very easily.

By the end of this session, having worked through the notes and exercises, and attended the in-person actvities, you should be able to:

  • Use Processing's built-in classes such as String and PVector;
  • Access fields stored in objects created from these and other classes using the dot operator;
  • Access methods stored in objects created from these and other classes using the dot operator;
  • Create your own class (class) containing fields and methods;
  • Create multiple objects from a class;
  • Refactor code to use classes and objects;

1. Using Processing's classes

We've used a number of different variable types so far in our sketches, each designed for storing different types of data. One such variable type was the type String, for storing text data. In fact, String is a special kind of type known as a class.

A class is like a normal variable type on steroids — not only can it be used for storing things, it also has its own methods for doing stuff with the data it stores. You can access those methods by using the 'dot operator' appended to the name of the variable. For example: 

String moduleTitle = "Creative Coding";
println(moduleTitle);
println(moduleTitle.length());

The first line just creates a new variable of type String. We've named the variable moduleTitle in this example. The second line just prints the content of that variable, just as we have done before. The third line calls one of the methods that comes with the String class, in this case one that counts the number of characters in the string.

The output sent to the console from these three lines is ... 

Creative Coding
15
... as there are 15 letters in the text 'Creative Coding' and the length() method that is part of the String class returns the number of characters held in the String.

The String class has plenty of other useful methods for doing things with text. Here are just a few of them: 

    String moduleTitle = "Creative Coding";
 
    println(moduleTitle.toUpperCase());  // Convert text to upper-case
    println(moduleTitle.substring(9));   // Extract part of string from 8th character onwards
        
    if (moduleTitle.contains("Cod"))
    {
        println("Fish related word found!");
    }
        
    if (moduleTitle.equals("Creative Coding"))
    {
        println("Upper-case match found!");
    }
        
    if (moduleTitle.equalsIgnoreCase("CREATIVE CODING"))
    {
        println("Case insensitive match found!");
    }

    if (moduleTitle.contains("eat") && moduleTitle.contains("Cod"))
    {
        println("Fishy food words found!");
    }

Producing the following console output: 

CREATIVE CODING
Coding
Fish related word found!
Upper-case match found!
Case insensitive match found!
Fishy food words found!

The PVector class

There are many, many classes that form part of the Processing language, and as we shall see later, you can create your own classes. But for now, one useful new Processing class is the PVector (see the Processing PVector reference).

#1 - PVector : a useful Processing class

A PVector is useful because it can store a pair (or a triplet when dealing with 3D data) of numbers representing coordinates such as those representing a position on screen. Here is a simple sketch that uses a PVector to draw a line between the centre of the screen and the mouse position: 

PVector screenPos;  // -- Declare a PVector object called 'screenPos' that will store a screen position.

void setup()
{
  size(400,400);
  stroke(150,74,50);
  fill(150,74,50);
  strokeWeight(6);
  screenPos = new PVector(width/2,height/2);    // -- Initialise screenPos - a PVector object - with two values.
}

void draw()
{
  background(243,142,45);
  // -- Access the 'x' and 'y' fields in the screenPos object and use them in calls to ...
  circle(screenPos.x,screenPos.y,12);             // -- circle() - to draw a circle
  line(screenPos.x,screenPos.y,mouseX,mouseY);  // -- line()   - to draw a line
}

void mousePressed()
{
  screenPos.x = mouseX;        // <-- this sets the x field of the screenPos PVector to the x position of the mouse (cursor)
  screenPos.y = mouseY;        // <-- this sets the y field of the screenPos PVector to the y position of the mouse (cursor)
}

The PVector variable is declared like any other, here in the first line. It is initialised with the special keyword new, like we did when creating arrays. In the case of PVector we specify the pair of numbers we wish to store (here, width/2 and height/2, but these could be any numbers, random numbers, negative numbers, anything). Once created, we can access those two numbers at any point in our code by using the name of the variable with a .x or .y appended.

A class is a description of the types of data that are to be stored and the methods that can be applied to those data. Using new to initialise a variable from a class is known as instantiation and the resulting data collection is called an object.
You can of course instantiate many objects from a single class - have many PVector objects in a single sketch.

You can think of a class as a template and objects as instances of the template. These templates model aspects of the world that we want to include in our sketches: like balls, and desktops, and graphs, and dogs and cats and those aliens that fly down at you in 80s arcade classic Phoenix.

Here, PVector is the class and, in our example, screenPos is the object we have instantiated from it. We can only call methods or extract data values using the dot notation applied to objects not classes. Well, usually! There are some exceptions to this rule, but we won't be considering them during the #CreativeCoding activity.

One of the main advantages of using classes is that it is very easy to create multiple objects from the same class (just as we might create multiple numeric variables from the float type). For example, we could create an array of PVector objects to extend our sketch to show several lines in response to mouse clicks: 

PVector[] clickedPoints; // -- An array to store all clicked positions.
int next;                // -- An integer to store the index of the next free (empty) position in the clickedPoints array

void setup()
{
  size(400,400);
  stroke(150,74,50);
  fill(150,74,50);
  strokeWeight(6);

  // -- Initialise the array with room for 5 points:
  clickedPoints = new PVector[5];
  // -- Add the sketch centre as first point - we are initialising the first element (index 0):
  clickedPoints[0] = new PVector(width/2,height/2);
  // -- Increment the position of the next free element by one:
  next = 1; 
}

void draw()
{
  background(243,142,45);

  // -- Loop through the elements of the array that contain values:
  for (int i = 0; i < next; ++i)
  {
    PVector p = clickedPoints[i];   // -- Store the PVector at the current index in a new local PVector.
    circle(p.x,p.y,12);             // -- Use the fields in this PVector as the centre of a circle.
    line(p.x,p.y,mouseX,mouseY);  // -- Use the fields in this PVector as the start of a line (that ends at the cursor).
  }
}

// -- When the mouse is pressed ...
void mousePressed()
{
  // -- If we have still got room left in our 'clickedPoints' array ...
  if (next < clickedPoints.length) {
    // -- Add a new PVector to the array at the 'next' free position:
    clickedPoints[next] = new PVector(mouseX,mouseY);  

    // -- Increment the next free position by one:
    next = next + 1; 
  }
}

In the example above, we add a new PVector object to those stored in an array every time the mouse is clicked, as long as the array is not full. The draw() method then uses a for loop to iterate over every PVector object in the array and draws a line from the mouse position to each of those PVector points in turn.

Note also that this example uses Processing's built-in method —void mousePressed() just as we have done before when getting our sketch to respond to mouse presses.

2. Creating your own classes

The real power of the Processing language is in the ability to create your own classes that store data and do stuff with those data: very cool stuff if you do a bit of creative thinking and have a play with the possibilities.

This really is amazing and exciting and gives us phenomenal power.
We don't just have to rely on the phenomenal enabling set of classes that come with the language.
We can make and model absolutely anything that we want to in a class. All we require is some imagination and some creativity.

To see why creating classes can be so useful, let's consider an extended example of getting a ball to move about inside our sketch.

The non-class approach

First, we will create a sketch to show a moving ball without creating any new classes. You will recognise some of the commands and logic from previous examples, but to make things a little simpler, we will use the PVector class to store the position (in x and y) and velocity (how much the position is changing in x and y) of the ball: 

PVector position;    // -- Position of the ball.
PVector velocity;    // -- Amount it moves on each redraw.
float radius;        // -- Radius of ball.
color colour;        // -- Colour of ball - using an object called 'colour' that is an instance of the 'color' class. 

void setup()
{
  size(400, 300);

  // -- Initialise our variables and objects ...
  position = new PVector(width/2,height/2);
  velocity = new PVector(random(-2,2),random(-2,2));
  radius = 15;
  colour   = color(214,93,69);
}

void draw()
{
  background(254, 244, 232);

  // -- Draw the ball.
  noStroke();
  fill(colour);
  circle(position.x,position.y,2*radius);

  // -- Update the ball position according to the velocity values.
  position.x = position.x + velocity.x;
  position.y = position.y + velocity.y;
}

There's little that's new here, but to recap, we declare four 'global' variables at the top of the sketch that will store the position of the ball, its velocity (in both the x and y directions), its radius and its colour. The setup() method initialises the variables with appropriate values and the draw() method draws the ball. Finally, the last two lines of draw() update the position variable according to the values stored inside the velocity object.

Remember that because draw() is called 60 times a second, the ball appears to move as we repeatedly update position by adding the values of velocity. The only problem we have with the sketch is that there's nothing to tell Processing when the ball reaches the edge of the sketch window. So as before, we'll add a few more lines to the bottom of draw() to test whether the updated position of the ball now places it outside the bounds of the sketch. If it does, we reverse the relevant component of the velocity by multiplying it by -1. 

PVector position;    // Position of the ball.
PVector velocity;    // Amount it moves on each redraw.
float radius;        // Radius of ball.
color colour;        // Colour of ball.

void setup()
{
  size(400, 300);

  position = new PVector(width/2,height/2);
  velocity = new PVector(random(-2,2),random(-2,2));
  radius = 15;
  colour   = color(214,93,69);
}

void draw()
{
  background(254, 244, 232);

  // Draw the ball.
  noStroke();
  fill(colour);
  circle(position.x,position.y,radius*2);

  // Update the ball position according to the velocity values.
  position.x = position.x + velocity.x;
  position.y = position.y + velocity.y;

  if (position.x - radius < 0 && velocity.x < 0)
  {
    // -- Escaping to the left, start moving right.
    velocity.x = -1*velocity.x;
  }
  else if (position.x + radius > width && velocity.x > 0)
  {
    // -- Escaping to the right, start moving left.
    velocity.x = -1*velocity.x;
  }

  if (position.y - radius < 0 && velocity.y < 0)
  {
    // -- Escaping upwards, start moving down.
    velocity.y = -1*velocity.y;
  }
  else if (position.y + radius > height && velocity.y > 0)
  {
    // -- Escaping downwards, start moving up.
    velocity.y = -1*velocity.y;
  }
}

Refactoring to use classes

So, is there a problem with the sketch above? It appears to work as we expect, and the code is relatively simple.

The problem is not with the sketch in its current implementation, but rather what we would have to do in order to extend it. In particular, suppose we wished to show 4 moving balls, as we did with the travelling circles exercise that we tried earlier in the course.

One solution might be to create 4 sets of variables, one for each ball, each storing the characteristics of a ball (its position, velocity, colour etc.). But that would make the program rather complicated and error prone. And wouldn't really work if we wished to show 100 or 1000 balls.

So the solution is to refactor the code, just as we did when we wished to remove duplicated code in the examples we tried when considering methods. This time, instead of creating new methods to represent the repeated sections of code, we will create a new class to contain the code that we wish to reuse. When we define a method we can reuse its code by calling it multiple times. As we will see, when we define a class, we can reuse its code by creating multiple objects from the class (these objects are said to be instances of the class). Our Ball class will not only have its own methods, but will also store the data that characterise and differentiate each ball instance, or object, that we create from the class.
Here we define a Ball class: 

class Ball
{
  PVector position;    // Position of the ball.
  PVector velocity;    // Amount it moves on each redraw.
  float radius;        // Radius of ball.
  color colour;        // Colour of ball.

  // -- This 'constructor' method is called when we instantiate a new ball and initialises its state.
  Ball()
  {
    position = new PVector(width/2, height/2);
    velocity = new PVector(random(-3,3),random(-3,3));
    radius = 15;
    colour   = color(214, 93, 69);
  }

  // -- These are methods associated with any instance of a Ball object.
  // -- draw() draws the ball at its current position.
  void draw()
  {
    noStroke();
    fill(colour);
    circle(position.x, position.y, radius * 2);
  }

  // -- move() moves the ball according to its current velocity and checks for boundary bounces.
  void move()
  {
    position.x = position.x + velocity.x;
    position.y = position.y + velocity.y;

    // -- Check for an edge and move the other way if one is detected:
    if (position.x-radius < 0 && velocity.x < 0)
    {
      // -- Escaping to the left, start moving right.
      velocity.x = -1*velocity.x;
    }
    else if (position.x+radius > width && velocity.x > 0)
    {
      // -- Escaping to the right, start moving left.
      velocity.x = -1*velocity.x;
    }

    if (position.y-radius < 0 && velocity.y < 0)
    {
      // -- Escaping upwards, start moving down.
      velocity.y = -1*velocity.y;
    }
    else if (position.y+radius > height && velocity.y > 0)
    {
      // -- Escaping downwards, start moving up.
      velocity.y = -1*velocity.y;
    }
  }
}

The first thing to note is that there is very little that is new here. It contains almost exactly the same code to declare and initialise the variables that represent the ball's position, velocity, size and colour; the same code to draw the ball and the same code to move it and check for boundary collisions.

The only differences are that we have placed each of those three behaviours (initialisation, drawing and moving) each in their own method, and that everything is placed within a pair of (highlighted) braces underneath the line that defines and manes the class: class Ball.

Making a Class is Easy!

To create a new class in Processing, simply use the keyword class followed by the name you wish to give the class and a pair of braces.

All the methods and variables associated with this class are then added within those braces. The class name itself should start with a Capital Letter.

So what we have created above is a new class that contains a set of variables (position, velocity, radius and colour) and a set of methods (Ball(), draw() and move()) that can each do something with those variables. Variables that are declared like this in a class (outside any method) are known as fields.

The first of those methods — Ball() is an important one. It has no return type (not even void), it shares the same name as the class itself (also called Ball) and is known as a constructor. A constructor is a special method that will be called automatically each time we create an object out of a class. This is a bit like setup() being automatically called when we first run a sketch. Just like setup(), you should put any lines of code that do initialisation or setup tasks inside the constructor. In our example, we initialise the position, velocity, size and colour of the ball in the constructor - our class 'setup()'.

Creating objects from a class

Our refactoring is not yet complete because although we have now written a class capable of representing a ball, we haven't actually created any balls. This is a bit like writing methods in a sketch, but not actually calling them.

To see how to create an object from a class, we need to revisit our main sketch code, which we can now greatly simplify since most of the hard work is done be the Ball class: 

Ball ball1;		// -- Declaration of a ball object from the Ball class.

void setup()
{
  size(400, 300);
  ball1 = new Ball(); // -- Initialization of the Ball called ball1.
}

void draw()
{
  background(254, 244, 232);
  ball1.draw();  // -- call the draw() method of the Ball ball1 - to draw it.
  ball1.move();   // -- call the move() method of the Ball ball1 - to move it and check for edges.
}

Our setup() and draw() methods are now much simpler because all the coding to do the initialisation, drawing and moving is contained in the separate Ball class.

What is new here is that in line 1 we have created a variable of type Ball (rather than, say, float or String) with this declaration. In the second line of setup() we then initialise a Ball object with the special keyword new. We name our Ball object ball1 here, but we could call it anything we wish, just like any other kind of variable.

Once we have created the ball1 object, we can call any of its methods by appending a dot and the method name to the object name. This follows exactly the same rules as we applied when creating objects from some of Processing's built-in classes such as String and PVector.

Yet, after all this work, our sketch still does exactly the same as the first version without any classes. The real advantage comes when we wish to create more than one object from the same class. Remember that we intended to create 4 balls in our sketch. Now that we have a class capable of representing any ball, all we need to do now is create 4 objects from that single class and ask each of them to initialise, draw themselves and move: 

Ball ball1;    // -- Declaration of a ball object from the Ball class.
Ball ball2;   // -- Declaration of another ball object from the Ball class.
Ball ball3;   // -- Declaration of a third ball object from the Ball class.
Ball ball4;   // -- Declaration of yet another ball object from the Ball class.

void setup()
{
  size(400, 300);
  ball1 = new Ball();  // -- We need to initialise all four declared Ball objects if we are going to use them in our sketch. 
  ball2 = new Ball();
  ball3 = new Ball();
  ball4 = new Ball();
}

void draw()
{
  background(254, 244, 232);

  // -- draw and move each Ball object in turn by calling its methods:
  ball1.draw();
  ball1.move();

  ball2.draw();
  ball2.move();

  ball3.draw();
  ball3.move();

  ball4.draw();
  ball4.move();
}

We can make things a little clearer still by storing those ball objects not as 4 separate variables, but in a single array, just like we did for PVectors previously: 

Ball[] balls;

void setup()
{
  size(400, 300);

  balls = new Ball[4];
  for (int i=0; i<balls.length; i = i+1)
  {
    balls[i] = new Ball();
  }
}

void draw()
{
  background(254, 244, 232);
  for (int i=0; i < balls.length; i=i+1)
  {
    balls[i].draw();
    balls[i].move();
  }
}

3. Manipulating Objects

As we have seen, one of the benefits of building a class from which objects may be instantiated is that it allows us to create many objects quite simply. The other important benefit is that the characteristics of each of those objects can be independent of all the other ones. So although all Ball objects have a position, velocity, size and colour, each ball object can have different values for position, velocity etc. We saw this was the case because in our example, the velocity of each ball was set to be a random value, which was different for each ball.

We could apply the same principle by setting the radius and colour of each new ball also to be random, by changing the code in the constructor of Ball: 

class Ball
{
  // Variable declaration here...
  // ...

  // Constructor
  Ball()
  {
    position = new PVector(width/2, height/2);
    velocity = new PVector(random(-2,2),random(-2,2));
    radius = random(1,25);
    colour   = color(random(160,230), random(50,110), random(70,120));
  }

  // Other methods here...
  // ...
}

Every time a new ball object is created using new Ball() the code in the constructor above will initialise the velocity, radius and colour fields with different random numbers.

We can also manipulate the values of these fields (also called 'instance variables') directly using the dot notation. This is exactly what we did with PVector when we manipulated its .x and .y values. So, for example, we could create a new Ball object (here called specialBall, but this could be any name you choose) and set its colour and size to some new values: 

Ball specialBall = new Ball();
specialBall.radius = 30;
specialBall.colour = color(100,100,200);

Note that this code would not be placed inside the Ball class, but inside the sketch that creates Ball objects from the class.

We could update the position on a mouse click by adding code that updates the position to the mouseClicked method. 

void mouseClicked() {
    specialBall.x = mouseY;
    specialBall.y = mouseX;
}

As a final example, here is how we might create a set of 40 random moving balls and one special ball of a different colour, that when it makes contact with any other ball, it 'infects' it by changing the colour of the infected ball. This is done by using Processing's dist() method to calculate the distance between the special ball and each of the others in turn to find out whether they are less than their two radii apart: 

Ball[] balls;
Ball specialBall;
color infectedColour;

void setup()
{
  size(500, 500);
  infectedColour = color(40, 200, 200);
  balls = new Ball[50];
  for (int i=0; i<balls.length; i = i+1)
  {
    balls[i] = new Ball();
    balls[i].colour = color(random(150, 220), random(60, 90), random(60, 120));
    balls[i].radius = random(4, 16);
  }

  specialBall = new Ball();
  specialBall.radius = 30;
  specialBall.colour = infectedColour;
  specialBall.position.x = 0;
  specialBall.position.y = 0;
  specialBall.velocity.x = 0.3;
  specialBall.velocity.y = 0.1;
}

void draw()
{
  background(254, 244, 232);
  for (Ball ball : balls) // a for-each loop
  {
    ball.draw();
    ball.move();

    // See if any ball makes contact with special ball.
    if (dist(specialBall.position.x, specialBall.position.y,
      ball.position.x, ball.position.y) < specialBall.radius+ball.radius)
    {
      ball.colour = infectedColour;
    }
  }

  specialBall.draw();
  specialBall.move();
}

In Summary ...
  • A class is a template that describes what data (fields) its objects will contain, and that provides methods to act upon that data.
  • An object is an instance of a class. The data values in each object exist independently of all other objects created from the same class.
  • Processing has many built-in classes from which you can create objects, such as String and PVector.
  • You can create your own classes using the class keyword followed by a name with a capital letter and a pair of braces within which the data and methods that form the class are coded. Each class has one special method called the constructor that will always have the same name as the class in which it sits and will be used to initialise the data when an object is created from the class.
  • To call the methods of an object, you name the object followed by a dot and the method name. The method then usually does something with the data stored in the object.
  • Classes and objects, like methods, are a way of making your code much more flexible, clearer to read and easier to maintain.
